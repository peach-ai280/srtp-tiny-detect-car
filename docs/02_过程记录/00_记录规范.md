# 记录规范

> 记录不是为了留档，是为了**三个月后能重建当时的判断**。写不出来的，等于没发生。

---

## 一、四类记录，各管一件事

| 类型 | 回答什么问题 | 频率 | 存放 |
|---|---|---|---|
| **周报** | 这一周实际发生了什么 | 每周日 22:00 前 | `周报/YYYY-W##.md` |
| **会议记录** | 谁承诺了什么、决定了什么 | 每次组会/评审 | `会议记录/YYYY-MM-DD_主题.md` |
| **实验记录** | 这个数是**怎么测出来**的 | 每次有效实验 | `实验记录/EXP-YYYYMMDD-NN.md` |
| **决策记录（ADR）** | 为什么选了 A 不选 B | 每个有代价的决定 | `决策记录/ADR-000N_主题.md` |

**最小要求**：宁可短，不可空。一份只有五行但全是真话的周报，比一份结构完整全是"有序推进中"的周报有用一百倍。

---

## 二、命名与编号

```
周报/          2026-W43.md           （ISO 周，跨年注意：2027-W01 可能落在 2026-12 末）
会议记录/       2026-10-26_建仓与立规矩.md
实验记录/       EXP-20261103-01.md   （日期 + 当天第几组实验）
决策记录/       ADR-0001_双板架构.md
交接/          2026-11-07_李海洋.md
```

- 日期一律 `YYYY-MM-DD`，不写"11月3日"。
- 实验编号**只增不复用**。同一实验做了三次，就是 `-01/-02/-03`，不要覆盖。
- 文件名不用空格（用下划线），不用括号、不用 emoji——URL 里会变乱码。

---

## 三、周报：五栏，其中一栏是必填的

```markdown
# 2026-W43（10-19 ~ 10-25）· 陶家宇

## 本周交付（对着上周承诺念）
- [x] 答辩材料定稿（10-20）：21 页 PPT + 逐页讲稿
- [x] 材料全文自检并修正 3 处
- [ ] 【未完成】H743 核心板比价 —— 原因：等王紫怡回复；延期到 W44

## 本周实测数据
| 项 | 数值 | 单位 | 怎么测的 |
|---|---|---|---|
| —  |     |      |          |

（没有就写"本周无新测数据"，不要留空）

## 卡点与求助
- 卡点：无 / 具体是什么、试过什么
- 需要谁帮：@某人 + 具体请求

## 下周承诺（可验收）
- [ ] 周一前把仓库推上 GitHub，交付：链接 + 首条 commit
- [ ] 周四前产出 M1 的硬件清单 v2

## 本周 AI 使用（必填，没有就写"无"）
- 用途：
- 涉及交付物：
- 未使用于：任何实验数据、任何引用条目
```

**三条硬规则**：

1. **"本周实测数据"不留空**。没有新数据就明确写"无"——空着会让人误以为忘了填，写了"无"才是信息。
2. **未完成必须写原因和新的日期**。只写"未完成"等于没交。
3. **下周承诺必须可验收**。"继续研究模型量化"不是承诺；"周三前跑通一次 INT8 转换，输出转换日志"是承诺。

## 四、会议记录：只记能追责的部分

```markdown
# 2026-11-02 组会

- 时间/地点/时长：
- 到会：陶家宇、李海洋、徐熠冉、王紫怡（请假：—）
- 记录人：李海洋

## 1 上周承诺兑现
| 人 | 承诺 | 结果 |

## 2 卡点
| 谁 | 卡在哪 | 试过什么 | 需要谁 |

## 3 决定（有决定才写这一节）
- 决定：M7 主责由 陶家宇 → 王紫怡
- 理由：M5–M8 单人负荷过高（风险 R-03）
- 反对意见：无 / 谁提了什么，为什么没采纳

## 4 本周承诺
| 人 | 承诺 | 验收方式 |

## 5 待办（非本周）
```

**不记**：讨论过程的来回、谁说了句什么俏皮话、情绪。**要记**：决定、理由、反对意见、承诺、日期。

**缺席者补写**：按 [实验室规矩](../04_团队/02_实验室规矩.md) 第四条，第一次无故缺勤由本人补写当次会议纪要。

## 五、实验记录：这是最重要的一类

**一个数字没有实验记录，就等于没有这个数字。** 写论文、答辩、被质疑时，能救你的只有这一份。

```markdown
# EXP-20261103-01 · H743 上 st_yolo_lc_v1 首次推理耗时

## 目的
验收 M1 指标：官方模型能否在板上跑起来，实测资源是否与 model zoo 账目相符。

## 环境（缺一项，结果就不可复现）
- 板卡：STM32H743VIT6 核心板，批次/丝印：
- 时钟：480 MHz，Flash 延迟设置：
- 工具链：STM32CubeIDE x.y.z / X-CUBE-AI x.y.z
- 模型：st_yolo_lc_v1，输入 192×192，INT8，来源（commit/版本）：
- 电源：USB 供电 / 电池 __ V，实测电压 __ V
- 室温：__ ℃（功耗类实验必填）

## 步骤
1. …（按顺序，细到别人能照做；固件路径写上）

## 原始数据（照抄，不加工）
| 次数 | 推理耗时 ms | 备注 |
|---|---|---|
| 1 |  |  |

## 结论
- 观测到：…
- 与预期/文献的差异：…（差异必须解释，解释不了就写"未解释"）

## 异常与怀疑
- 有没有哪次数据明显不对？为什么保留/剔除？（剔除必须给理由，不许悄悄删）

## 附件
- 日志：`results/raw/EXP-20261103-01.log`
- 截图：
```

**五条纪律**：

1. **原始数据照抄**，不要先在 Excel 里"顺手算个平均"再写进来。平均值单独放结论。
2. **异常值不许删**。要么解释清楚为什么剔除，要么留着并在结论里讨论。
3. **环境写全**。室温、电压、固件版本——功耗和帧率的实验，少一样就没法复现。
4. **测三次以上**。单次数据不当结论，至少给 min/median/max。
5. **"未解释"是可以写的**。写"这个差异我们还没搞清楚"，比编一个解释强。

## 六、决策记录（ADR）：写给三个月后想推翻它的人

```markdown
- 日期：2026-10-26
- 状态：已采纳

## 背景
（当时面对什么约束）

## 选项
| 方案 | 优点 | 缺点 |
|---|---|---|
| A | | |
| B | | |

## 决定
选 A。

## 理由
（三条以内，能验证的优先）

## 代价与风险
（承认这个决定的坏处）

## 什么情况下应该推翻它
（这一栏最重要——不然三个月后没人敢动它）
```

## 七、什么不进仓库

| 内容 | 原因 | 放哪 |
|---|---|---|
| 数据集原始图像、视频 | 体积大，git 不适合 | 网盘/移动硬盘，`data/` 只放说明与数据卡 |
| 训练产物（.h5 / .tflite / .onnx 大文件） | 同上；可用 Release 或模型库 | `models/` 放说明与校验和 |
| 芯片手册 PDF、厂商 SDK | 版权 + 体积 | 各人本地；`docs` 里只写链接与版本号 |
| 含个人隐私的画面（宿舍、人脸、车牌） | 合规 | 不入库、不外传；采集时避开 |
| 未公开的第三方代码/数据 | 授权 | 不入库 |

**判断标准**：这个文件会不会超过 5 MB？会不会一年后有人来问"你们凭什么有这个"？答"会"就不进仓库。
