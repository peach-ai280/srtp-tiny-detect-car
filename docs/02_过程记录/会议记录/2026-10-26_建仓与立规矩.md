## 3 决定

**决定一：建 GitHub 仓库，先文档后代码。**
- 理由：项目要跑九个月，四个人，跨学期。没有仓库，所有上下文会在寒假断一次。而且结题材料要能追溯"这个数怎么来的"。
- 决定内容：主仓 `srtp-tiny-detect-car`，文档入库，数据与大文件不入库（见 [记录规范](../00_记录规范.md) 第七节）。
- 反对意见：无。李海洋提出"代码还没写，先建仓会不会太空"——回答：**空着比没有好，空着至少能看出进度是零。** 而且 M1 就要交相机出图，代码很快会有。

**决定二：采纳《实验室规矩》v1.0。**
- 理由：四个人都是大一，课表不齐，寒假会断；不提前写清楚请假和缺勤怎么处理，到真发生的时候会变成互相体谅、然后互相埋怨。
- 覆盖条款：请销假、病假与工作协调、无故缺勤、消极怠工、滥用 AI、对自己负责的模块不熟悉。
- 关键设计：**后果落在署名和模块归属上，不落在情绪上。** 我们开不了人，能调整的只有分工和排序。
- 反对意见：徐熠冉提出"记黄牌会不会太严，大一怕吓跑人"——采纳为修订：规矩第八节加"每学期末复盘一次，哪条执行不下去就删"，且明确"提前说不接活"不算怠工。

**决定三：双板架构记 ADR。**
- 理由：这是有代价的决定（多一块板、多一处联调风险），以后一定会有人问"为什么不用一块板"。
- 交付：[ADR-0001](../决策记录/ADR-0001_双板架构.md)

**决定四：分工按 M1–M12 定稿，每个模块设 A/B 角。**
- 理由：四个人九个，一定会有人病、有人考试。只有一个人懂的模块 = 全组停摆。
- 当前最大风险：M5–M8 全压在负责人身上，已记 R-03，M3（端侧推理）通过后必须分出 M7/M8。
- 交付：[分工与交接](../../04_团队/03_分工与交接.md)

**决定五：M9/M10（底盘联调、IMU/编码器采集）立即并行推进，不等采购。**
- 理由：这是唯一"现在就能动手、不依赖 H743 到货"的活。等板子到了再一起开工，等于把 M1 的六周浪费掉。
