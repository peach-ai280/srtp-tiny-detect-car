# ADR-0001 · 采用双板架构（F103 底盘 + H743 感知）

- 日期：2026-10-26
- 状态：已采纳
- 决议人：陶家宇（技术负责人）　｜　组会通过

---

## 背景

申报书写的是"STM32"，未限定具体型号。实际情况是：

- 底盘已经有一块 **F103C8T6**，配 DRV8833 驱动和 60 mm 麦轮，随机器人竞赛搭好并跑过；
- 目标检测的资源账（ST model zoo 实测）：192×192 INT8 检测模型需 **Flash 330 KB、RAM 174 KB**。F103C8T6 只有 64 KB Flash / 20 KB RAM，**差一个数量级**，装不下。
- 所以必须加一块能跑模型的板子，问题只在于"怎么加"。

## 选项

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A | 单板：H743 同时管感知与电机 | 少一块板；时序天然统一；只有一套固件 | 要重写已跑通的底盘固件；电机 PWM 与 DCMI/DMA 争中断与总线；一块板挂了整车不动，**调试时改感知就动不了车** |
| B | **双板：F103 管底盘 + H743 管感知** | 底盘固件不动（已验证）；感知可单独在桌面上调；故障隔离——感知崩了还能手动遥控 | 多一条串口协议；两块板时钟不同步；多一处供电与固定问题 |
| C | 换树莓派 / Jetson Nano 做感知 | 算力充裕，模型随便跑 | **偏离"MCU 端侧部署"这个题目本身**；功耗与启动时间不适合小车；成本翻几倍；而且这等于把项目变成"调用现成推理库" |

## 决定

**选 B。**

## 理由

1. **保住已验证的东西。** F103 底盘是唯一"已经能跑"的部分，重写它的风险远大于多接一条串口。
2. **调试效率。** 感知开发阶段会有几十次改模型、改分辨率的迭代，每次都要重新烧整车固件是不可接受的。双板下感知板可以单独摆在桌上，接 USB 就能测。
3. **题目约束。** 方案 C 会让"在 MCU 上部署"这件事消失，等于换了个项目。这不是保守，是守住选题。

## 代价与风险（承认，不粉饰）

| 风险 | 具体是什么 | 缓解 |
|---|---|---|
| 串口带宽与延迟 | 感知结果（框坐标 + 三档判定）走 UART，帧率 4 fps 时带宽不是问题，但**最坏时延会增加** | 协议设计成定长小包；实测往返延迟记入 EXP；> 10 ms 则改 SPI |
| 时钟不同步 | 两块板各自计时，时间戳对不上会让帧间补位失效 | 感知板出帧时打 tick，底盘以 tick 为准做对齐；同步误差目标 < 5 ms（M10 验收项） |
| 供电 | H743 满负荷 + 摄像头 + 超声，18650 可能掉压复位 | 徐熠冉算电流余量（本周承诺）；必要时加 DC-DC 或单独供电 |
| 固定与走线 | 第二块板要固定在车上，杜邦线在颠簸中会松 | 打 3D 打印支架（预算里已留 350 元测试加工费）；关键线改焊接或加锁扣 |

## 什么情况下应该推翻这个决定

- 串口往返延迟实测 > 10 ms 且优化不下去 → 改 SPI 或共享内存方案；
- 供电余量算下来不足 30% → 先加 DC-DC，仍不足则考虑把超声/舵机单独供电；
- 里程碑 3 发现 H743 的 DCMI/DMA 与串口收发严重互相干扰 → 评估是否合并到单板。

**如果以上都没发生，就不要再讨论"要不要合成一块板"。** 已经决定过的事反复讨论，是最贵的浪费。

## 影响

- 硬件预算：+130 元（H743 核心板），核心器件合计 178 元 / 材料费额度 450 元——见 [BOM](../../../hardware/bom.csv)
- 分工：M9/M10 归王紫怡（底盘与采集），M5–M8 归陶家宇（感知侧）
- 里程碑 1 的验收标准增加一条：**两板串口通信打通，往返延迟有实测值**
