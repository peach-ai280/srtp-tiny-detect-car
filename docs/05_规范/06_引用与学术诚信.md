# 引用与学术诚信

> 这份文件只管一件事：**你说的每个数、每句话，别人能不能翻到出处。**

---

## 一、数字必须有出处

报告、PPT、论文里出现的每一个外部数字，都要能追到原文。

| 数字 | 出处 | 说明 |
|---|---|---|
| 105.8 ms | [R2] ST model zoo | H735 @550 MHz，SSD-MobileNetV1-0.25 192×192 INT8，纯推理 |
| 240 ms | [R1] Deploy-SSD-ON-STM32 | H743 + OV5640，端到端，mAP 31.8%，4–5 FPS |
| 359 ms | [4] TinyissimoYOLO | H7A3 @192 MHz，单帧 |
| 174.38 KiB / 330.21 KiB | [R2] `st_yolo_lc_v1` | 192×192 的激活 RAM / Flash 账 |
| 7.2 cm | **我们自己算的** | 0.3 m/s × 240 ms，算术，不是文献值 |

**诚实标注"这个数是我们算的"和"这个数是别人测的"，同样重要。** 把推算值写成实测值，是这个项目最容易犯也最致命的错。

**规矩**：写"据某文所述"之前，先打开那份 PDF 找到那句话。找不到就不能写。**"我印象中是"不算出处。**

## 二、引用格式

正文用方括号编号 `[1]`，与 [文献调研报告](../01_立项/04_文献调研报告.md) 的编号一致（该编号又与 `参考文献原文/` 的文件编号一致，形成三重对应）。

文末列表用简化 IEEE 风格：

```
[1] L. Lai, N. Suda, V. Chandra, "CMSIS-NN: Efficient Neural Network Kernels for Arm Cortex-M CPUs," arXiv:1801.06601, 2018.
[4] D. Bonetto et al., "TinyissimoYOLO: A Quantized, Low-Memory-Footprint, Low-Power Object Detection Network for Microcontrollers," IEEE Access, 2024.
[R1] Flora233333, "Deploy SSD on STM32," GitHub repository.
```

**开源项目用 `[R1]`–`[R3]`**，与论文编号区分开。

## 三、AI 与引用（重点）

**AI 会编造参考文献。** 这不是偶发，是它在"看起来合理"这件事上的固有倾向：作者名、会议名、年份、DOI 都能编得像真的，甚至能编出一个格式完全正确但根本不存在的条目。

所以：

1. **AI 生成的引用条目一律不采信**，必须打开原文逐条核对：作者、标题、发表处、年份。
2. **核对过的**才能进列表。核对时顺手记下 PDF 的文件名（我们的编号就是文件名）。
3. 已经踩过一次：AI 检索出的两条文献信息与实际 PDF 在年份和会议名上有出入，按原文改了。**这类错误如果没有被发现，会在答辩时被人当场问出来。**

细节见 [AI 使用规范](01_AI使用规范.md)。

## 四、代码与图片的来源

| 用别人的东西 | 要做的事 |
|---|---|
| 开源代码（nanodet [R3]、TFLite Micro [7] 等） | 查仓库 LICENSE；保留版权声明；在 README 里列出用了什么、什么版本；**改过的地方标注** |
| 论文里的图、表 | **不直接复制**。要引用就重画，并注明"数据来源 [n]" |
| 网络图片、他人照片 | 不用。要用就找明确可商用的，或自己拍 |
| 同学/学长给的材料 | 先问能不能用、要不要署名。**别人给的不等于可以随便用** |

**LICENSE 用前必查，不要凭印象。** Apache-2.0、MIT、GPL 的义务完全不同，尤其 GPL 会传染到我们的代码——如果用了 GPL 的库，我们的仓库可能也得 GPL。**这个判断在动手写代码前做，不是结题前。**

## 五、署名的三条

1. 署名按 [团队章程](../04_团队/01_团队章程.md) 第五节执行：实际贡献 + 能否讲清。
2. **指导教师按惯例置末位通讯作者**，投稿前与老师确认。
3. 结题报告里每人负责的章节与模块，必须与 [分工与交接](../04_团队/03_分工与交接.md) 对得上。**对不上就是有人的贡献没写清，或者有人写了不属于自己的。**

## 六、负结果

**"没做通"是最容易被写坏的部分。**

| 不要写 | 要写 |
|---|---|
| "初步验证了该方法的可行性"（其实没降下来） | "误动作率从 18% 降到 14%，未达到 50% 的预期目标。原因分析见下" |
| "受条件限制，未完成 X" | "X 因 ___（具体原因）未完成，已有数据为 ___，缺口是 ___" |
| 删掉不理想的实验组 | 保留，并说明为什么这组数据偏离预期 |

**为什么值得较真**：结题答辩时，主动说"这条没做通，我们知道原因"，换来的是"这孩子靠谱"；而被问出来"你上次说的 50% 呢"，换来的是对所有其他数字的怀疑。**一个数字的可信度是会传染的。**

## 七、致谢里要写什么

- 指导教师：具体帮了什么（不是"悉心指导"，是"帮我们否掉了 S2 的原始定义，改成输出层统计"）
- 提供设备/场地的实验室、师兄师姐：写明具体帮助
- 资金：重庆大学第十九届大学生科研训练计划（SRTP）资助

**具体的致谢比华丽的有分量。** 而且它同时是一份"谁帮过我们"的记录，以后写推荐信、找导师时有用。
