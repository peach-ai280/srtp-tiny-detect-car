# 数据管理规范

> 核心原则：**图像不进仓库，但必须可复现；标注可以重建，但版本不能含糊。**
> 配套文件：[数据卡](../../data/数据卡.md) ｜ [标注说明](../../data/README.md)

---

## 一、为什么图像不入库

- 800 张 JPEG 约 100–200 MB，git 会永久保存每个版本的副本，仓库会迅速膨胀到无法 clone；
- 数据集还可能涉及第三方版权与采集时的隐私（宿舍、人脸、车牌）。

所以：**仓库只存"怎么来的、怎么标的、怎么划分的"这三件事，不存图本身。**

---

## 二、目录结构（本地 / 网盘，不入库）

```
dataset/
  v0.1/
    images/                 # 原始图像，只读，改了就废了
      000001.jpg
      000002.jpg
    labels/                 # YOLO 格式标注，与图像同名
      000001.txt
    classes.txt             # 类别顺序（顺序即 id，不许改）
    splits/
      train.txt             # 每行一个文件名，不含扩展名
      val.txt
      test.txt
    manifest.sha256         # 全部文件的校验和，用于验证数据集完整性
```

**`images/` 一旦定版只读。** 发现某张图标错了，不改原图，而是：记进 `errata.md`（哪张、错在哪、什么时候发现的）→ 在下一版修。**改过的数据集必须有新版本号。**

## 三、标注

- **格式**：YOLO txt，每行 `class_id cx cy w h`，坐标按图像宽高归一化到 0–1，保留 6 位小数。
- **类别**：≤ 3 类（多了训不动，也没必要）。当前定：`0 material_box`（物料盒）、`1 obstacle`（其他障碍）、`2 hand`（人手，用于测试误检）。
- **标注规则要写成文**（`data/标注说明.md`），至少写清：遮挡多少算可见、边界裁切的框怎么画、模糊到什么程度不标。
- **抽检**：每 100 张抽 10 张复核，一致率 < 95% 就全量重标。**一致率要记录**，写在数据卡里。

标注工具不限（labelImg / Label Studio / X-AnyLabeling 都行），但**须在数据卡里写明工具与版本**——不同工具的默认导出格式有差异。

## 四、划分

| 集合 | 比例 | 用途 |
|---|---|---|
| train | 70% | 训练 / 微调 |
| val | 15% | **阈值标定、风险—覆盖率曲线**（这是最常被误用的集合） |
| test | 15% | **只在最后用一次** |

**划分是一次性的，写进 `splits/*.txt` 并入库。** 用固定种子（`--seed 42`）生成，之后不许重划——重划之后，"上次的 val 精度"就没法和这次比了。

**val 与 test 不能混用。** 用 test 调过阈值，test 就不再是 test。这条规则很烦，但破坏它的代价是**结论不可信**。

**划分要防泄漏**：连续视频帧不能一半在 train 一半在 val（同一场景会"背答案"）。按**采集批次**划分，不按帧随机划分。

## 五、版本与校验

```
dataset v0.1  2026-11-xx  320 张  初版，仅物料盒
dataset v0.2  2026-12-xx  640 张  加 obstacle，重打光
dataset v1.0  2027-01-xx  820 张  定版，用于量化与全部实验
```

- 每个版本生成 `manifest.sha256`：`find . -type f -exec sha256sum {} \; > manifest.sha256`
- 版本号写进每次实验记录（[实验记录模板](../02_过程记录/实验记录/_模板.md) 的"环境"栏）
- **论文/报告里报的所有精度，必须注明数据集版本。** 不写版本的数字没法比较。

**备份**：本地一份 + 网盘一份。大一最惨的事故是硬盘坏了、数据没了、三个月白干。**数据只存一个地方等于没存。**

## 六、隐私与合规

| 要求 | 做法 |
|---|---|
| 不采集人脸、车牌、宿舍内景 | 拍摄时避开；不可避免时在采集现场就换角度，不靠后期打码 |
| 如画面中出现可识别的他人 | 该帧剔除，并在数据卡记录剔除数量与原因 |
| 不采集校园敏感区域（实验室门禁、设备铭牌） | 拍摄前看一遍背景 |
| 数据集不外传 | 不给其他团队、不上传公开网盘；结题后按学校要求处理 |

**这条不是形式主义。** 一组大一学生拍了几百张走廊照片，其中如果有别人的脸，被传到 GitHub 上是真会出事的。

---

## 七、日志与实测数据

- 原始日志放 `results/raw/`，**命名与实验编号一致**：`EXP-20261103-01.log`
- 日志可以入库，但**单个文件 > 5 MB 的不入**（超了就先抽样或压缩）
- 处理后的汇总表放 `results/`，格式见 `results/指标表_模板.csv`
- **每一行汇总数据都要能追到一份原始日志**——这是"能不能被质疑"的分界线

## 八、检查清单

采集/整理完，对着过一遍：

- [ ] `images/` 与 `labels/` 文件名一一对应，没有孤儿文件
- [ ] `classes.txt` 与标注里的 id 一致，顺序没变
- [ ] 每类至少 100 个实例（少了训不出来，要如实写在数据卡里）
- [ ] 含"负样本"（画面里没有目标的帧），否则模型会到处乱框
- [ ] 含困难样本：逆光、模糊、遮挡、侧视、反光地面各若干
- [ ] `splits/` 三份都生成了，且按采集批次划分
- [ ] `manifest.sha256` 已生成
- [ ] 数据卡填完（见 [数据卡](../../data/数据卡.md)）
- [ ] 已备份到第二个物理位置
