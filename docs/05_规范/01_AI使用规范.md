# AI 使用规范

> 版本 **v0.9（草案）**　｜　2026-10-26 起草　｜　与 [实验室规矩](../04_团队/02_实验室规矩.md) 第六节配套，同批待组会通过
>
> **为什么这条要先立**：AI 写作已经是我们这届的日常，藏着不用反而可疑。把"哪些能用、哪些不能、用了怎么标"写在前面，比被问起来临场解释划算得多。

---

## 一、立场

AI 是工具，和示波器、CubeMX 一样。**问题从来不是"用没用"，是"用完之后你还会不会"。**

我们这条项目里，AI 能帮的事很多：解释一个从没见过的报错、把一段寄存器配置翻译成人话、给测试用例打个骨架、把中文摘要改顺。这些用了不丢人。

真正会出事的是两种情况：一是**拿 AI 编出来的东西当实验结果**；二是**交出去自己讲不清的代码**。第一种是造假，第二种是自欺——评审一问就穿，而穿帮的时候没人会记得你哪部分是自己写的。

所以规范只有两条底线：

1. **数据不能是 AI 生成的**（一个数字都不行）；
2. **交付物必须讲得清**（参见规矩第七条的三问）。

## 二、能做什么、不能做什么

| 场景 | 判定 | 说明 |
|---|---|---|
| 查报错、解释编译信息、看懂数据手册某一段 | ✅ 随便用 | 相当于搜索引擎加翻译 |
| 解释概念（INT8 量化怎么做的、DMA 为什么快） | ✅ 随便用 | 但结论要回到原始文档核一遍 |
| 生成样板代码（串口初始化、I2C 读寄存器、CSV 解析） | ✅ 可用，需读懂 | 提交时在 PR 里注明哪几个函数是 AI 起草 |
| 写单元测试的骨架、造测试输入 | ✅ 可用 | 测试逻辑要自己定，别让它替你决定"什么算对" |
| 改文档措辞、翻译、压缩摘要 | ✅ 可用 | 报告里用了要在文末声明（见第五节） |
| 解释一段别人的开源代码 | ✅ 可用 | 引用时按原仓库 LICENSE 走 |
| 帮你设计实验方案 | 🟡 参考可以 | 方案要自己能讲出每一步为什么，别照抄 |
| 生成论文正文段落 | 🟡 需大改 | 只能当草稿；每句都要能溯源到自己的实验或引文 |
| 生成参考文献条目 | ❌ 禁止直接使用 | AI 会编出不存在的论文、作者、DOI。**必须逐条打开原文核对** |
| 生成/推测实验数据、精度、耗时、温度 | ❌ 绝对禁止 | 造假。一次就够毁掉整个项目 |
| 整段代写代码，自己没读懂就提交 | ❌ 禁止 | 见规矩第七条 |
| 把队友的任务丢给 AI，交上去算自己的 | ❌ 禁止 | 侵占 |

## 三、必须声明的地方（三处，缺一处算记录缺失）

1. **周报**：每周必填一栏，没有就写"无"。格式：

   ```markdown
   ### 本周 AI 使用
   - 用途：查 CMSIS-NN 的 arm_convolve_s8 参数含义 / 改周报措辞
   - 涉及交付物：firmware/perception/src/infer.c 中的 dma 初始化部分（AI 起草，我重写过一遍）
   - 未使用于：任何实验数据、任何引用条目
   ```

2. **提交信息**：AI 参与起草的代码提交，在正文末尾加一行：

   ```
   [ai-assisted] 串口DMA初始化由AI起草，已按参考手册RM0433第xx节核对并改写
   ```

3. **报告与论文**：文末单独一节（放在致谢前）：

   ```markdown
   ## AI 工具使用声明
   本文写作过程中使用 <工具名> 辅助：英文文献摘要翻译、文字润色。所有实验数据、
   图表、结论均由作者本人完成并负责；文中引用条目均已核对原文。AI 未参与数据分析
   与结论形成。
   ```

   如果期刊/会议有指定格式，按期刊要求写。投出去之前查一遍目标刊物的 AI 政策——有的要求更严。

## 四、怎么用才不废掉自己（给大一的实话）

大一最容易踩的坑不是"用了 AI"，是**用 AI 跳过了本该练手的那一段**。三个月后你会发现：代码能跑，但你不知道它为什么能跑；报错能修，但换一个报错就懵。

三条建议，都是笨办法，但有效：

1. **先自己写一版能跑不通的，再去问。** 哪怕写得很烂。你带着"我试过 A、B，报了这个错"去问，得到的答案你能消化；带着"帮我写一个"去问，得到的代码你只能粘贴。
2. **AI 给的每一行，都要能说出它在干什么。** 说不出来的行，删掉重写，或者去查手册。允许慢，不允许糊。
3. **让它解释，而不是让它决定。** "为什么这里要用 volatile"是有价值的问题；"这段怎么改才能编译过"往往让你错过真正的原因。

判断自己有没有被废掉，有个很土的标准：**关掉 AI，能不能把一个已经跑通的模块从零再写一遍骨架？** 能，就是工具；不能，就是拐杖。

## 五、违规处理

| 情形 | 处理 |
|---|---|
| 未声明 | 补声明，不追究 |
| 未声明且涉及核心交付物 | 记记录缺失一次，下次评审重点问该模块 |
| 讲不清自己提交的代码 | 该部分重做；重做后仍讲不清，不计入个人贡献 |
| 数据来自 AI 生成或推测 | **相关数据全部作废重测**，本人当次里程碑红牌，组会通报 |
| 引用 AI 编造文献 | 全文引用复核，报指导教师，当次里程碑红牌 |
| 用 AI 顶替他人工作 | 该交付物不计入个人贡献，记红牌 |

处理结果一律记入 [风险登记册](../06_风险与变更/01_风险登记册.md)，写事实与日期，不写评价。
