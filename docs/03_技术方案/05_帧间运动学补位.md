# 创新点 ③：帧间运动学补位

> 状态：**设计稿 v0.1**（2026-10-26）。
> **定位声明：这是工程创新，不是方法创新。** 高频惯性补低频视觉是控制领域的成熟常识。我们的价值在定点实现、几十 KB RAM 约束下的可用性，以及收益的量化。

---

## 一、问题的时间轴

```
检测帧   0 ms ───────── 240 ms ───────── 480 ms ───────── 720 ms
         │                 │                │                │
         ▼                 ▼                ▼                ▼
控制环   ●─●─●─●─●─●─●─●─●─●─●─●─●─●─●─●─●─●─●─●─●─●─●─●   （100 Hz，每 10 ms 一次）
         每 240 ms 更新 24 次，其中只有 1 次拿到新检测
         其余 23 次：位置靠陀螺 + 编码器推演
```

**把 240 ms 前的旧框直接喂给 PID，等于给控制环加了一个固定相位滞后。**

后果是可预测的：车会画龙（左右摆动）、过冲（冲过目标再回来）、在障碍前反复修正（进进退退）。这三件事在低速小车上尤其明显，因为低速时积分项积累慢、修正更迟钝。

**这是控制里的常识，但在五十块钱的四轮小车上没人认真处理**——因为大家默认"摄像头 30 fps"，而我们的摄像头只有 4 fps。

## 二、推演模型（平面 3-DoF，够用就好）

### 2.1 位姿更新

$$
p(t) = p(t_0) + R(\Delta\theta)\, v \, \Delta t, \qquad \Delta\theta = \int_{t_0}^{t} \omega \, d\tau
$$

其中 $p$ 是障碍在车体系下的位置 $(x, y)$，$v$ 是车速，$\omega$ 是陀螺角速度，$R(\Delta\theta)$ 是二维旋转矩阵。

离散化（10 ms 一拍，用梯形或直接用上次采样的 $\omega$）：

```
for each 10 ms tick:
    dθ  = ω * dt                      // 陀螺读数，去零偏后
    p.x = p.x - v * dt * cos(dθ/2)    // 车前进 → 障碍在车体系后退
    p.y = p.y - v * dt * sin(dθ/2)
    p   = R(-dθ) * p                  // 车转向 → 障碍坐标旋转
```

**符号约定必须先想清楚**：车往右转（$\omega > 0$），左前方的障碍在车体系里会往右移。这一条写错，车会往反方向躲——**这是这类实现最经典的 bug，第一次调试大概率会撞上，别怀疑是传感器坏了。**

### 2.2 不确定度

不引入协方差传播（那需要完整的 EKF）。用**显式线性增长**：

$$
\sigma(t) = \sigma_0 + k \, \Delta t
$$

- $\sigma_0$：检测本身的位置误差（按框宽度的一个比例，如 10%）；
- $k$：单位时间增长速率，标定方式——让车静止、只让 **检测在动**，测 $\sigma$ 随 $\Delta t$ 的变化，线性拟合出 $k$；
- **上限**：$\sigma$ 超过阈值（如框宽的 50%）就**停止推演，直接进 U 档**（交给创新点 ② 复核）。

$$\sigma(t) > \sigma_{\max} \Rightarrow \text{放弃推演，报存疑}$$

**为什么不做卡尔曼**：EKF 需要过程噪声、观测噪声的协方差矩阵，四五个参数要靠调，而且调错了表现得像"玄学"。显式线性增长只有一个参数 $k$，**好解释、好调、错了也好找**。答辩时被问"为什么不用 EKF"，答案就是这句：**参数越少，越可能在九个月内调对。**

## 三、定点实现

F103 没有 FPU（Cortex-M3），浮点运算靠软件模拟，一次乘除几十个周期。100 Hz 下每拍只有 10 ms = 720k 周期，浮点其实够用——**但没必要浪费**。

| 量 | 表示 | 精度 |
|---|---|---|
| 位置 $p$ | Q8.8，单位 mm | 1/256 mm ≈ 4 µm（远超需要） |
| 角度 $\theta$ | Q1.15，单位 rad | 3×10⁻⁵ rad |
| $v$ | int16，单位 mm/s | 1 mm/s |
| $\omega$ | int16，单位 0.01 rad/s | |

**三角函数**：不调 `sinf/cosf`。用 256 点查表 + 线性插值，表占 512 B（int16 × 256）。

$$\cos(\theta) \approx \text{LUT}[\lfloor \theta \cdot N/2\pi \rfloor] + \text{frac} \cdot (\text{LUT}[i+1] - \text{LUT}[i])$$

误差 < 0.1%，对 4 fps 的检测精度而言完全够。

**每拍开销估算**：约 200–400 周期（含查表与两次乘加），10 ms 预算里占不到 0.1%。**这个开销可以忽略，所以实现上不用抠。**

## 四、怎么证明它有用（实验设计）

**唯一变量原则**：同一段路线、同一组参数、同一个起点，只切换"补位开/关"。

| 项 | 设置 |
|---|---|
| 路线 | 一条固定的避障路线（3 个障碍，含 1 个直角转弯），地面贴标记保证起点一致 |
| 次数 | 每组 20 次（`n=20`，够算中位数与非参数检验） |
| 速度 | 固定 0.3 m/s（W 档速度） |
| 变量 | A 组：补位开；B 组：补位关（旧框直接喂 PID） |
| 记录 | 底盘 100 ms 日志（时间、档位、目标速度、实际速度、指令差分量） |

**两个指标**

1. **轨迹最大横向偏差**：用地面标记或顶视摄像头量，取整段路线的最大值（不是平均——画龙看的是峰值）。
2. **电机指令差分的 RMS**：$\text{RMS}(\Delta u) = \sqrt{\frac{1}{N}\sum (u_i - u_{i-1})^2}$，反映"抖动"。

**预期**：两条曲线能明显分开（A 组偏差小、抖动小）。

**统计上怎么说**：20 组数据用中位数 + 四分位距报，配一个 Mann-Whitney U 检验（不假设正态）。**不写 p 值也行，但必须给分布，不能只给一个平均数。**

## 五、失败判据

以下任一成立，就如实写"补位在这个场景下没有明显收益"，并按 [ROADMAP](../../ROADMAP.md) 的卡点预案处理：

- 两组横向偏差的中位数差异 < 10%（说明 240 ms 的滞后不是主导误差）；
- RMS 抖动无显著差异；
- 帧率本身达不到 4 fps（补位的前提不成立，先解决 ①）。

**这也是有用的结论**：它给出了"什么时候才需要补位"的边界——比如"当检测频率低于控制频率的 1/10 时才明显"。**这个边界比"我们做了补位"更有信息量。**

## 六、已知薄弱点

1. **只推主框**。多目标时其余框不动（它们会"卡"在旧位置）。这是刻意的简化，代价是遮挡场景下辅助目标会漂。
2. **$\sigma$ 的线性增长是拍的模型**。真实误差增长可能是指数或饱和的，但这需要大量数据标定；线性模型至少**方向是对的**（越久越不准）。
3. **轮式里程计会打滑**。麦轮横向移动时编码器读数与实际位移差异大，$\theta$ 靠陀螺还行，$v$ 在横移时不可信——**所以推演里只用车体前进方向的速度，横移时降权**。
4. **依赖底盘回传 $(v, \omega)$**，如果串口丢包，推演会用到过期数据 → 超过 100 ms 未更新则 $\sigma$ 加速增长（实现上：把 $\Delta t$ 用"上次更新时间"算，而不是当前时间）。

## 七、实现计划

| 阶段 | 时间 | 内容 |
|---|---|---|
| 离线仿真 | M2 | PC 上用日志回放，验证推演公式与符号（**先在没有车的情况下把符号调对**） |
| 底盘实现 | M3 | F103 上实现 Q8.8 定点推演 + 查表三角，输出到调试变量 |
| 闭环 | M4 | 接上视觉框，跑固定路线，A/B 两组各 20 次 |
| 数据分析 | M5 | 出两张分布图 + 统计检验，写入报告 |

**离线仿真是省钱的一步**：符号弄反了在仿真里一眼看出来，在车上要撞十次才知道。
