# 创新点 ①：帧级可信度判定

> 状态：**设计稿 v0.1**（2026-10-26）。核心假设尚未验证——**这份文档里没有一条是结论。**
> 相关：[指标口径](06_指标定义与验收口径.md) ｜ [触发式复核](04_触发式定向复核.md)

---

## 一、要解决的问题

检测网络对每一帧都会给出框和分数。问题是：**分数高 ≠ 这一帧对。**

两种情况都会骗人：

1. **过度自信**：逆光、运动模糊、遮挡时，模型给出 0.9 分，但框是错的（[10] 系统讨论过这个现象）；
2. **量化误差**：INT8 部署后，输入分布稍有偏移，激活就大量撞上量化上界，输出悄悄失真——**浮点模型上根本看不到这个过程**（[8] 的量化方案是这一现象的理论来源）。

所以我们不追求"分数更准"，而是**额外给出一个判断：这一帧整体靠不靠得住。**

---

## 二、四个信号

设计原则：**全部来自推理过程本身**，不加网络分支、不跑第二个模型、内存增量在个位数 KB。

| 信号 | 定义 | 计算方式 | 额外开销 |
|---|---|---|---|
| **S1** 分数间隔 | 最高分框的 top1 与 top2 类别分数之差 | INT8 域直接相减，不反量化、不跑 exp | 几十个周期 |
| **S2** 量化饱和率 | 被 clamp 到 ±127 的激活值占比 | 见第三节（**这是本项目的核心押注**） | 见第三节 |
| **S3** 帧间一致性 | 当前框与"由上一帧 + 底盘运动预测出的位置"的偏差 | IoU + 中心位移残差，定点算 | < 1 ms |
| **S4** 输出熵（对照组） | 最高分框类别分布的熵 | LUT + 整数移位做定点近似 | < 1 ms |

**为什么 S4 是对照组**：它是最"标准"的不确定性度量，如果 S4 单独就能干得很好，那我们的 S2 就没有存在价值。**必须做这个对照，否则说不清创新点到底是不是 S2。**

---

## 三、S2 量化饱和率：核心押注，也是最大的工程风险

### 3.1 它是什么

INT8 量化把实数映射到 `[-128, 127]`，超出范围的值被 clamp（截断）。当输入图像偏离校准时用的分布（比如训练集是白天室内，实测是逆光走廊），大量激活值会撞上 ±127。

$$
\text{sat} = \frac{\#\{a_i : a_i = 127 \ \text{或}\ a_i = -128\}}{\#\{a_i\}}
$$

浮点模型没有这个概念——它只会在数值上"稍微大一点"。**所以这是一个只在部署后才存在的可观测量。**

### 3.2 工程难题：Cube.AI 是黑盒

理想做法是在每个卷积层后统计 clamp 次数。但 Cube.AI 生成的是**不开放的 C 代码**，拿不到中间激活。

三条路，我们按代价从低到高试：

| 方案 | 做法 | 能不能运行时用 | 代价 |
|---|---|---|---|
| **P1（先用这个）** | 只统计**输出张量**的饱和率——后处理本来就要读 int8 输出，顺手统计 | ✅ 能，零额外成本 | 只反映最后一层，信息量少 |
| **P2（主力）** | 在 Cube.AI 生成的代码里，对**最后 1–2 个卷积层**的输出加统计钩子（改生成的 `*_data_*.c` 或包一层） | ✅ 能 | 需要读懂生成的代码；重新生成工程时要重新打补丁（用脚本自动打） |
| **P3（退路）** | 改用 TFLite Micro 部署，算子可 hook | ✅ 能 | 性能可能不如 Cube.AI；把部署链路重做一遍 |

**判断**：P1 一定可行，先跑通它拿到第一批数据。P2 是真正想要的东西，如果读生成代码太痛苦就退回 P1，并在报告里写清楚"只统计了输出层"——**这比含糊地说'我们用了饱和率'诚实得多。**

> 这一节是本项目最可能卡住的地方。**列在这里，是为了四个月后卡住时不慌**，而是知道下一步走 P3。

### 3.3 成本估算

P1：读输出张量时顺带数一遍，192×192 输出层若有 ~2000 个值，几十微秒。
P2：每层插桩增加一次遍历，估 < 2 ms（待实测）。
内存：无额外分配，只是计数器。

## 四、融合规则（先规则，后学习）

### 4.1 第一版：规则 + 分位数阈值

不训练任何东西，阈值全部由验证集分位数定：

```
输入：s1, s2, s3, s4（各自归一化到 0–1）
if  (s2 > T2)                    → R（弃用）      # 饱和率过高：量化已经失真
elif (s1 < T1a) and (s3 < T3)    → U（存疑）      # 两个独立信号都说不好
elif (s1 < T1b) or  (s3 < T3)    → W（可用，但降权）
else                              → W（可用）
```

阈值定法：取验证集上**错误帧**分布的第 70 百分位作为 T2、第 60 百分位作为 T1a/T3。**先粗调，再按风险—覆盖率曲线扫。**

### 4.2 第二版（可选）：逻辑回归

四个信号 → 一个概率。参数只有 5 个，PC 端用 numpy 训，C 里手写 10 行定点代码即可。**比规则更平滑，但会失去"可解释"这个优点**——答辩时"为什么这个帧被判存疑"能指着某个信号说清楚，比说"回归输出 0.43"有用。

**倾向**：如果规则的曲线已经够用，就停在规则。**简单能解释的东西，在这个项目里比多 1 个点的 AUC 值钱。**

## 五、怎么评价（这一节决定创新点成不成立）

用 [9] 的**风险—覆盖率曲线**（risk–coverage）：

- **覆盖率 coverage** = 1 − 触发率。触发率 = 被判 U 或 R 的帧占比；
- **风险 risk** = 在"被接受的帧"里，错误帧的占比；
- **错误帧定义**（必须在实验前写死，不许事后改）：与真值 IoU < 0.5，或类别错，或应有框而无框。

理想曲线：提高覆盖率时风险缓慢上升。我们的目标点：

| 指标 | 目标 | 说明 |
|---|---|---|
| 错误帧召回 | **≥ 70%**（在触发率 ≤ 30% 时） | 70% 的错误帧被拦下来 |
| 触发率 | **≤ 30%** | 超过这个数，平均时延与降速代价就吃掉收益 |
| 定点 vs 浮点判别力损失 | **≤ 5 个点** | 证明定点实现没把信号算废 |

**对照实验（必须有，否则说不清贡献）**：

1. 只用 S1（最朴素的基线）
2. 只用 S4（标准的不确定性度量）
3. 用 S1+S3+S4（不含 S2）
4. **全用（含 S2）**

第 3 与第 4 的差别，就是 S2 的净贡献。**如果差别不明显，就如实写"饱和率没有带来额外判别力"——那也是一份结果，而且是我们最可能得到的结果之一。**

## 六、失败的判据（提前写死）

以下任一成立，就判定"这条路走不通"，转入负结果写作：

- 在触发率 ≤ 30% 时，错误帧召回 < 50%（说明信号没有分辨力）；
- 任何组合都做不过"只按置信度阈值"的基线（说明我们加的信号没用）；
- S2 在所有场景下都接近 0 或接近 1（说明这个量在我们的数据上根本没有变化）。

**写入方式**：结题报告里单列一节"不可信判定的有效性边界"，把这个负结果和所有曲线一起交。**负结果在这里是有价值的**，因为公开的负结果比正结果少得多——这本身是可发表的东西。

## 七、实现计划

| 阶段 | 时间 | 做什么 | 产出 |
|---|---|---|---|
| 离线验证 | M2（2027-02 前） | PC 端用 TFLite/ONNX 跑量化模型，逐帧算 S1–S4，画风险—覆盖率曲线 | `tools/eval/` 下的评估脚本 + 第一批曲线 |
| 板端落地 | M3（2027-04 前） | S1/S3 先上板（成本低），S2 按 P1 方案；跑通实时输出三档 | 判定模块代码 + 板端耗时 |
| 阈值标定 | M4（2027-06 前） | 用实车数据重标阈值；接上触发复核做闭环 | 标定记录 + 实车对比数据 |
| 对照实验 | M4–M5 | 四组组合对比，出净贡献 | 数据表 + 论文"实验"节 |

**离线先行**是关键：PC 端一天能跑几千帧，板端一天只能测几十次。**大部分结论应该在 PC 上先得到，板上只验证"能不能实时跑"。**

## 八、已知的薄弱点（自己先说出来）

1. **S2 在 Cube.AI 上可能拿不到**（第三节）。这是最大的风险，退路已列。
2. **错误帧的定义有主观性**。IoU 0.5 是惯例，但对"避障"这个任务，也许"框中心偏 3 cm"才是有意义的错误。用 IoU 是为了和文献可比，**不代表它对应真实的碰撞风险**。
3. **四信号相关性可能很高**。S1 与 S4 都是类别分布的度量，可能高度冗余，"四信号"实际上是"两信号"。这一点要靠相关性分析（实验前先算一遍相关系数矩阵）确认，**如果冗余，就如实说"实际有效的只有两个信号"**。
4. **样本量**。数据集只有几百到一千张，风险—覆盖率曲线的尾部会很不稳。**结论只能说到趋势，不要说精确到小数点。**
