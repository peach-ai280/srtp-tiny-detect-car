## 评估怎么组织

三层，从下往上：

```
① 逐帧信号     signals.csv     每帧：S1 S2 S3 S4 + 是否错误的标签
② 扫阈值       sweep.csv       每个阈值组合：触发率、召回
③ 出图         figures/*.png   风险—覆盖率曲线、A/B 分布
```

**先有 ① 才有资格谈 ②③。** 很多项目直接跳到画图，结果曲线是用几个手挑的点连出来的——那不算评估。

## 逐帧信号表（`signals.csv`）

| 列 | 含义 |
|---|---|
| `frame` | 帧文件名 |
| `split` | train / val / test |
| `n_gt` | 真值框数 |
| `n_pred` | 预测框数 |
| `grade_pred` | 判定输出（W/U/R） |
| `s1` `s2` `s3` `s4` | 四个信号值（0–1 归一化） |
| `iou_max` | 主框与真值的最大 IoU |
| `cls_ok` | 主框类别是否正确（0/1） |
| `is_error` | **按定义算出的错误帧标签**（0/1），定义见 [指标口径](../../docs/03_技术方案/06_指标定义与验收口径.md) |

`is_error` 这一列必须用脚本算，**不能人工标**——人工标会不自觉地偏向"这个我觉得应该算错"。

## 风险—覆盖率曲线怎么画

1. 对每个可能的阈值组合，算触发率与召回；
2. 横轴 `coverage = 1 − 触发率`，纵轴 `risk = 被接受帧里错误帧占比`；
3. 四条线画在同一张图上：只用 S1 / 只用 S4 / S1+S3+S4 / 全用（含 S2）；
4. 标出目标点：触发率 30% 处，看召回是多少。

**第 3 条是关键**：只有把"不含 S2"和"含 S2"画在一起，才能看出 S2 有没有净贡献。**如果两条线几乎重合，就如实写"饱和率没有带来额外判别力"**——这是最可能的结果之一，也是值得写出来的结果。

## A/B 对比（补位开/关）

| 项 | 做法 |
|---|---|
| 数据 | 两组各 20 次运行，每次取下表两个量 |
| 指标 | 轨迹最大横向偏差 (cm)、电机指令差分 RMS |
| 怎么报 | 箱线图 + 中位数与四分位距（**不只报均值**） |
| 检验 | Mann-Whitney U（不假设正态，n=20 够用） |
| 结论怎么写 | "中位数从 X 降到 Y（降 Z%），U 检验 p=..."；**p 值不显著就说不显著** |

## 画图的规矩

- 图必须**由脚本生成**，不许手调。手调的图三个月后没法更新。
- 每张图存两份：`.png`（入库，< 500 KB）+ 生成它的命令写在实验记录里。
- 坐标轴**必须有单位**。`时间 (ms)` 不是 `时间`。
- 不要用双 Y 轴（除非万不得已），容易误导。
- 报告里引用的图，文件名要有意义：`risk_coverage_s2_ablation.png`，不是 `fig1.png`。
